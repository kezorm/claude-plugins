# The asset-log method — v1.6.0

> **Verbatim copy. Do not edit this file.** It is identical in every record
> created from the asset-log skill, which is what makes it replaceable: to
> update, overwrite it from the skill and review `../CLAUDE.md` for conflicts.
> Anything specific to *this* thing belongs in `../CLAUDE.md`. `md5sum` it
> against the skill's copy to see whether this record is current; changes are
> listed in the skill's `CHANGELOG.md`.

A record of a thing someone owns, not a software project. **A fact recorded in
one file and contradicted in another is worse than not recording it at all.**

---

## Structure emerges; it isn't prescribed

**Make a folder when a document arrives that needs one, not before.** A car
record grows `service/`, `reference/labels/`; a house grows `permits/`,
`appliances/`, `insurance/`. Guessed-at empty folders invite documents into the
wrong place.

---

## Two jobs, two clocks

A record tells you **what needs attention now** (the ranked open items in
`README.md`) and **answers questions later** (everything else). Don't let the
first eat the second.

- **"Does this change anything?" is the wrong test for an archival fact.** A
  paint code changes nothing today and is what you want in 2035.
- **Capture completely; triage separately.** Transcribe the whole plate, not
  the two fields that matter this week.
- **Write for a reader arriving in ten years knowing nothing.** Spell out the
  abbreviation, say *why* a decision was made, name the vendor and the town.

## The core rule

**When new information arrives, propagate it everywhere it belongs — in the
same sitting, before calling it done.** Three layers, every time:

1. **The artifact** — original preserved intact, sensibly named, with a text
   extraction beside it if it's a PDF
2. **Whatever write-up covers that subject**
3. **`README.md`** — status, open items, upcoming. **The one people forget.**

**Spoken facts are filings too** — *"I replaced the filter last week"* gets
logged with part numbers and a date. If something genuinely changes nothing at
the top, say so rather than skipping silently.

## Document roles

Roles, not paths — the paths differ between records.

| Role | Rewritable? |
|---|---|
| **The status document** (`README.md`) — the only description of *current* state | **Yes — always rewrite to stay true** |
| **Reference** — specs, parts, part numbers | Yes, as facts firm up |
| **Logs** — what was done, when | Append; don't rewrite history |
| **Dated analyses** — what was believed *at that time* | **No — never rewrite.** Annotate additions; supersede rather than edit |

### Correcting what's already written

**The test is not "was this wrong?" It is "did anyone rely on it?"**

- **Nobody did** — fix it silently, leaving no trace in the prose. The old text
  is in the commit history.
- **Someone acted on it** — money spent, work skipped, a part ordered — then it
  goes in the **log** as a dated entry, not as a scar inside a reference
  document.
- **Dated analyses** are snapshots. Additions go in as dated notes; when one is
  overtaken, write a new one and mark the old **Superseded**, pointing forward.

**A record earns trust by being accurate, not by displaying its scars.**

## Filing

1. `bin/inbox-status` — see what arrived
2. **Read every file before filing it.** The filename is a guess; the contents
   are the fact.
3. **Deduplicate by checksum** — people re-send things
4. Put it where its content says it belongs, making the folder if needed
5. **Rename so a human can read it** — `survey-2019-04-11.pdf`, not
   `Document_2019_scan0043.pdf`. Renaming in bulk? Keep a provenance file
   mapping new names to originals.
6. `bin/extract-text` — a `.txt` beside every PDF, `bin/eml-text` beside every
   `.eml`. **The highest-leverage habit here.** See the table warning below.
7. **Transcribe photographed labels into text.** A photo of a data plate isn't
   data until the numbers are searchable.
8. Write up what it says
9. **Update `README.md`**
10. `bin/check-links`
11. **Commit with a message stating what was learned, not what moved**

```
Add April service; refrigerant leak suspected

Technician notes the system was 1.2 lb low on a 5.8 lb charge — about 20%.
Opened as item 2. Humidifier item closed; the invoice shows it was done.
```

**Steps 8 and 9 are where a filing pass fails silently.** A find-and-replace
that matches nothing reports success, so **assert the anchor matched, then check
`git status`.** Verify a bulk edit by re-deriving the result from the source,
never by the loop finishing — a partly-failed bulk edit looks exactly like one
that worked.

### Purchase paperwork: the money is the fact

Rank an order's paper trail and keep the top of the stack:

1. **The payment record** — receipt, refund, statement line. Governs everything below
2. **The invoice** — what shipped, at what price, with what discount
3. **A confirmation carrying a per-item status** — the only thing showing a line was cancelled
4. **A plain confirmation** — what was asked for, not what arrived
5. Dispatch and status notices — tracking that resolves at no carrier in five years

- **A confirmation is not an invoice.** A cancellation or return leaves it
  reading as though the part was supplied. **Look for the return before trusting
  the total.**
- **The vendor's own corrected total is not the payment either.** If money
  moved, find the record of the money.
- **When culling, keep whatever carries a per-item status**, and transcribe the
  amounts before deleting a payment record.
- **Record the vendor's stated reason for a cancellation.** *"No longer
  available"* is a fact about the world, not about the order.

## Evidence standards

Someone spends money against these conclusions.

- **Tag confidence.** **[confirmed]** — from the item itself or its official
  documentation. **[verify]** — the typical value, not yet checked against this
  one. Never state a part number, capacity or interval as fact because it is
  typical.
- **Write down what a pending document is expected to settle — and what it will
  not.** A predicted value is falsifiable and worth having: *"the plate behind
  the bumper should read `41531`"* either holds or exposes a problem. An
  unstated assumption that a document will answer a question is how a gap gets
  closed on paper and not in fact.
- **Absence of a record is not evidence of absence.** Write *"no record of X
  since \<date\>"* — never "was skipped", "was missed", "was never done". Same
  caution for thin data: zero reports on an uncommon item is weak evidence, not
  a clean record.
- **Anything read off a photograph is a proposal** — not just numbers, but which
  part it is, its condition, whether it is even present. Keep
  `[confirmed — owner]` distinct from an assistant's reading. **"I can't see it"
  is not "it isn't there."** Detail: `references/evidence.md`.
- **A reading has two parts, and the tag only covers one.** The value, and the
  field it belongs to. Where a label is illegible and the field was assigned by
  position or layout, **say that it was** — `[confirmed — owner]` on the digits
  says nothing about the guess as to what they mean.
- **When sources conflict, record the conflict and name which one governs.**
- **Separate urgency from importance.** Inflating a finding spends the
  credibility you need when something genuinely is urgent.
- **Flag your own weakest claim.** Every research pass has one.
- **Grep each figure back out of its source before committing a write-up.**
- **Don't trust an extracted table without checking a row.** `pdftotext`
  rebuilds columns from character positions and gets tables wrong *silently* —
  it has produced a wrong replacement interval for a part whose failure destroys
  an engine. Verify one value independently; anchor each row to *its own page's*
  header. When the tables **are** the content, re-extract with a structure-aware
  tool — `uvx docling --to md file.pdf`. `bin/extract-text` flags tabular files.
- **Watch for the calendar limit.** Where something has both a usage interval
  and a time limit, work out which binds first. On lightly used things the
  calendar usually wins, and nothing on the item warns you.

## Conventions

- Dated folders and files use `YYYY-MM-DD`
- Keep every original **and** its text extraction
- Estimated readings carry a leading `~` (`~12,400`) with one line nearby saying
  what bounds the estimate
- `_inbox/` contents stay untracked until triaged
- Verify links before committing
- **When something tabular gets repetitive** — fill-ups, hours, seasonal swaps —
  put the data in a CSV and let a script compute the summary into the README

## Self-containment

**Everything needed to work on this record is in this record.** Nothing depends
on an assistant's memory, a subscription, or one machine. If you learn something
that matters, write it into a file here — that is the only place it counts.

---

## Before sharing

**Going public is one-way** — clones, forks and mirrors are not recalled by
flipping visibility back. Private-first is the reversible order; adding
collaborators is not publication.

**Audit before sharing:** the owner's own information (prices, identifiers,
addresses, and commit metadata, which carries name and email), third-party
copyrighted material, and anything about other people.

If a public version is wanted, make it a **separate repository with fresh
history**, carrying the method and none of the documents.
